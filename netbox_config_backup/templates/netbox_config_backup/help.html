Recommended setup

Start with one representative device. Reuse profiles only after the first test succeeds.

  1. Create connection and credential profiles Define reusable connection settings and credentials for devices that share them.
  2. Create a platform mapping Select the driver and defaults for the device's NetBox platform.
  3. Add and test a device Save the backup device, test connectivity, then run its first manual backup.
  4. Add an FTP storage if needed Test the FTP storage and copy existing revisions before relying on replication.
  5. Review retention Open Retention preview on the device before enabling Local cleanup or FTP cleanup.

How a backup moves

A successful device backup and an FTP copy are related, but they are separate operations.

1. Collect from device The selected driver connects with the effective connection and credential profiles.
2. Hash and store locally The plugin hashes the artifacts. It creates a ConfigRevision according to the backup policy, or links an unchanged run to the latest matching revision.
3. Replicate new revisions to FTP Each enabled FTP storage with automatic copying receives an independent immutable copy of every new revision.
A temporary FTP outage does not change a successful device backup to failed. The Local revision remains valid and the FTP copy can be retried without reconnecting to the device.

Local and FTP retention

Local and FTP retention are resolved separately. A profile selects what may expire; a scheduler performs the deletion.

Local profile precedence

  1. Local storage profile when Always use this storage's retention profile is enabled
  2. Local retention profile selected on the device
  3. Local retention profile from the backup policy
  4. Local storage profile as a fallback
  5. Keep indefinitely when no profile is available

FTP profile precedence

  1. FTP storage profile when Always use this storage's retention profile is enabled
  2. FTP retention profile selected on the device
  3. FTP storage profile as a fallback
  4. Keep indefinitely when no profile is available
Local cleanup and FTP cleanup are disabled independently. Preview retention on a device before enabling either scheduler. FTP deletion has no recycle bin.

FTP storage or device upload receiver?

They move data in opposite directions and cannot replace one another.

FTP storage

The plugin copies an already successful Local revision to your internal FTP server. Configure this under Storages.

Device upload receiver

A vendor driver asks the device to push a native export into the plugin. Use it only for drivers which explicitly require one.

FTP is unencrypted. Use it only on an isolated, trusted internal management network with a dedicated restricted account.

Common connection and storage errors

The reason code identifies which layer failed before you change device settings.

Show reason codes and first checks
HOST_KEY_UNKNOWN
The SSH identity has not been approved. Verify its fingerprint and approve it under SSH host keys.
AUTH_FAILED
The service is reachable, but the username, password, or allowed authentication method was rejected.
CONNECTION_REFUSED
The address is reachable, but no compatible service accepts the configured port.
TIMEOUT
Check the effective NetBox management address, route or VPN, firewall, protocol, and port.
COMMAND_UNSUPPORTED
Login succeeded, but this firmware does not support the driver's read-only configuration command.
DESTINATION_TEST_FAILED
The FTP login may work while directory creation, write, read-back, or probe cleanup is denied.
